## Why

The app can only work with models generated by CadQuery scripts. Users cannot bring their own 3D models (OBJ, STL, PLY, STEP, etc.) into the tool, which severely limits its usefulness as a papercraft tool — most papercraft models exist as downloaded mesh files, not CadQuery code. We need to support importing external models.

The challenge: mesh formats (OBJ/STL/PLY) don't map to the code-driven workflow (the editor and agent operate on CadQuery scripts). The answer is a hybrid: CAD solids (STEP/BREP) import as code (CadQuery imports them natively, so the agent keeps full editing), while triangle meshes (OBJ/STL/PLY/glTF) import as fixed mesh projects where the editor/chat are disabled and the user gets scale controls instead.

## What Changes

- Add an import button (upload icon) next to the "New project" button in the project selector. A native file picker (via `tauri-plugin-dialog`) selects a file; the extension determines the project type:
  - **CAD solids** (`.step`, `.stp`, `.brep`, `.dxf`) → code project: the file is copied into the project dir and `model.py` is generated with `cq.importers.importStep(...)` (absolute path). The agent retains full editing.
  - **Triangle meshes** (`.obj`, `.stl`, `.ply`, `.gltf`, `.glb`) → mesh project: the file bytes are read, parsed in the frontend via three.js loaders (`OBJLoader`, `STLLoader`, `PLYLoader`, `GLTFLoader`), converted to `MeshObject`, and stored as normalized `mesh.json` alongside the source file.
- Mesh projects store: `meta.json` with `mode: "mesh"` + a `scale` field, the original source file, and `mesh.json` (normalized vertices/faces). No `model.py`.
- Mesh projects disable the code editor and agent chat; the left pane shows an info box ("Imported model — cannot be edited as code") and a **scale control**. Scale is a mesh-transform (unit conversion) applied before unfold, keeping the print pipeline exact (1:1 relative to the scaled model).
- Export gains **STEP and BREP** via the Python sidecar (`cq.exporters.exportStep` / `exportBrep`). These are grayed out in the export menu for mesh projects (a mesh has no solid to export).
- New Rust commands: `import_mesh`, `import_cad_file`, `read_file`.

## Capabilities

### New Capabilities
- `model-import`: Import entry point (native file picker, format routing), the `import_mesh` / `import_cad_file` / `read_file` commands, and project creation from external files.
- `mesh-project`: The mesh project mode — `mode: "mesh"` in `meta.json`, normalized `mesh.json` storage, disabled editor/chat with info box + scale control, and scale-as-mesh-transform semantics.

### Modified Capabilities
- `project-management`: Projects gain a `mode` field (`code` | `mesh`); loading a mesh project returns the mesh + scale instead of a script.
- `model-export`: The export menu gains STEP/BREP options (Python-sidecar export), grayed out for mesh projects.
- `print-settings` / `print-output` / `page-tiling` / `mesh-simplification`: Unchanged behavior; mesh projects flow through the same unfold/print pipeline (with scale applied upstream).

## Impact

- **Code**: `src-tauri/src/` (new `import.rs`, `project.rs` mode handling, `python.rs`/runner export commands, `lib.rs` registrations), `src/components/projects/ProjectSelector.tsx` (import button), `src/components/print/PrintPreview.tsx` and `src/components/code-editor/` + `src/components/chat/` (mode-aware disabling), new scale control UI, `src/types/` updates.
- **Dependencies**: `tauri-plugin-dialog` (Rust + JS). three.js loaders already available in the bundle (no new JS dep).
- **No Python changes for import** — mesh parsing is three.js in the frontend; STEP/BREP import uses CadQuery's existing importers via generated code. The runner gains export helpers only.
